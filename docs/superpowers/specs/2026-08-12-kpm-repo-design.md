# KPM Repository & Migration Agent — Design

Date: 2026-08-12

## Purpose

The Kindle jailbreak community (KindleTweaks / Awesome-Kindle) is moving away from
KUAL as the latest Vera jailbreak no longer supports it. This project stands up a
KPM repository so tweaks currently listed in [Awesome-Kindle](https://github.com/KindleTweaks/Awesome-Kindle)
can be installed via KPM instead, starting with `disable_ads`, and builds a
repeatable migration process (a Claude Code skill) for converting future tweaks.

## Critical disambiguation

There are two unrelated projects both called "KPM":

- **`KindleModding/KPM`** by **Hackerdude** — <https://github.com/KindleModding/KPM>.
  Documented at kindlemodding.org; "as of `hdnext` it is the recommended
  distribution method for Kindle homebrew." **This is the tool this project targets.**
- **`Gingrspacecadet/KPM`** — <https://github.com/Gingrspacecadet/KPM> — a separate,
  unrelated "Package manager for kindle." It is even listed in Awesome-Kindle's own
  Miscellaneous section, which makes it easy to conflate. **Not used here.**

Every README, package manifest, and doc string this project produces must make clear
it targets Hackerdude's `KindleModding/KPM`.

## Repository

- **Host:** `github.com/Latif17/kpm-repo`, public repo, personal account (not yet
  announced to the community pending validation).
- **Topology:** monorepo. Package *sources* are hand-authored and version-controlled
  on `main`. The repository *index* (`manifest.json`) and built `.kpkg` artifacts are
  generated by CI and deployed to the `gh-pages` branch — never committed to `main`.
  This matches the documented pattern ("repositories can be hosted statically on
  GitHub Pages") and keeps generated binary artifacts out of source history.

```
kpm-repo/
├── README.md                        # disambiguation note, add-repo instructions, credits
├── LICENSE
├── sources/
│   └── disable_ads/
│       ├── manifest.json
│       ├── install.sh
│       ├── uninstall.sh
│       └── MIGRATION_NOTES.md       # provenance, upstream link, anything needing human review
├── tools/
│   ├── kpm-helper.py                # vendored from KindleModding/KPM, pinned
│   ├── SOURCE.md                    # upstream URL + pinned commit hash + CC0 license note
│   └── build.py                     # packs each sources/* dir, assembles the repo index
├── .github/workflows/publish.yml    # build on push to main, deploy to gh-pages
└── .claude/skills/migrate-tweak/SKILL.md
```

### Vendored `kpm-helper.py`

Copied from `KindleModding/KPM` at commit `ffa767fffadd731bd59f2bca8c83231f4fc0ab2d`
(CC0-licensed). `tools/SOURCE.md` records the upstream URL, the pinned commit, and the
license, so future updates are a deliberate re-pin rather than a silent upstream
change breaking the build.

### Build & publish

`tools/build.py` wraps `kpm-helper.py`:
1. For each directory under `sources/`, run `package pack sources/<id> build/`.
2. `repo init` (first run) / `repo add` for each built `.kpkg` to assemble the index
   into `dist/` (`manifest.json` + `packages/<id>/artifacts/*.kpkg`).

`.github/workflows/publish.yml` runs this on push to `main` and deploys `dist/` to the
`gh-pages` branch, which is what an on-device KPM install points at as the repo URL.

## Package conventions

- `id`: lowercase, ASCII alphanumeric plus `-`/`_` only (KPM's own validation rule —
  packing fails otherwise).
- `author`: the *original* tweak author (e.g. "Marek" for `disable_ads`), not
  KindleTweaks or the migrator. Attribution is preserved.
- `version`: starts at `1.0.0` when the upstream source has no version scheme of its
  own.
- `supported_platforms`: `null` (all platforms) unless there's concrete evidence a
  tweak is hardware-specific.
- Every package must have a working `uninstall.sh`. Where the underlying tweak is
  naturally reversible, uninstall must actually restore prior state (see
  `disable_ads` below) rather than just deleting the package's own files.

## `disable_ads` package

Source: `https://scriptlets.notmarek.com/scriptlets/disable_ads.sh` (author: Marek).
Original behavior: deletes `/var/local/adunits` and `/mnt/us/.assets`, flips
`adunit.viewable` to `false` in `/var/local/appreg.db`, reboots after 5 seconds.

This is destructive and, as originally written, irreversible — deleted files and an
overwritten DB flag with no restore path. The migrated package makes it reversible:

**`install.sh`:**
1. If invoked with `upgrade` as `$1`, skip step 2 (an existing backup from the
   original install must not be clobbered by a mid-upgrade state).
2. Otherwise, if no backup exists yet at `/mnt/us/documents/.kpm_disable_ads_backup/`:
   move `/var/local/adunits` and `/mnt/us/.assets` into that backup dir, and record
   the current `adunit.viewable` value (queried via `sqlite3`) to a file there —
   *before* touching anything.
3. Apply the original disable steps (remove folders, set `adunit.viewable` to
   `false`).
4. Reboot after 5 seconds, matching upstream behavior exactly (confirmed with user:
   KPM install is already an explicit action, so the automatic reboot is expected).

**`uninstall.sh`:**
1. If invoked with `upgrade` as `$1`, do nothing — this call is part of an upgrade,
   not a real uninstall, and must not restore ads mid-upgrade.
2. Otherwise, if the backup dir exists: move `adunits` and `.assets` back to their
   original locations, restore the saved `adunit.viewable` value into `appreg.db`,
   delete the backup dir, and reboot after 5 seconds to apply the restoration.
3. If no backup dir exists (edge case: ads were never actually present/enabled at
   install time), print a clear message that there is nothing to restore and exit 0.

`MIGRATION_NOTES.md` for this package records the upstream source URL, author, the
date fetched, and a note that automatic reboot + backup/restore behavior was a
deliberate design decision, not an inferred guess — for the next person (or the
migration agent) auditing this package.

## Migration agent (`/migrate-tweak`)

A Claude Code skill at `.claude/skills/migrate-tweak/SKILL.md`, invoked with a source
(raw script URL, GitHub repo URL, or local path). It is **advisory and interactive**,
not a fire-and-forget script — the whole point is that ambiguous or destructive
decisions (reboot behavior, rw remounts, missing reversibility, platform targeting)
get surfaced to a human rather than guessed.

Steps the skill follows:
1. Fetch/read the source and classify the tweak type: single scriptlet, KUAL
   extension (has `config.xml`/`menu.json`), or a full external app/repo.
2. Derive a valid package `id` from the tweak name (lowercase, `-`/`_` only).
3. Draft `manifest.json`, preserving original author attribution and description.
4. Translate the tweak's logic into KPM hooks:
   - single scriptlet → `install.sh` places it (or wires a `launch.sh` that invokes
     it via the `kpm launch` convention), `uninstall.sh` removes it.
   - KUAL extension → parse `menu.json` actions and `config.xml`, map each menu
     action to an install step or a `launch.sh` invocation.
5. Identify anything destructive, irreversible, or platform-specific and stop to ask
   the user how to handle it — it does not silently choose a default the way the
   `disable_ads` reboot/backup decisions above were explicitly confirmed rather than
   assumed.
6. Scaffold `sources/<id>/` with the manifest, hooks, and a `MIGRATION_NOTES.md`
   summarizing what was auto-generated vs. what still needs human verification.
7. Does **not** run `tools/build.py` or touch `gh-pages` — building and publishing
   remain explicit, separate, human-triggered steps.

## Explicitly out of scope

- Submitting packages to the official `KindleModding/repo` — its submission process
  is undocumented ("TBA" in their own README) as of this writing.
- On-device hardware validation. Scripts here modify system files and trigger reboots
  on a real Kindle; no tool available in this session can validate that behavior.
  Testing on actual hardware before any package ships remains a manual step for the
  user.
